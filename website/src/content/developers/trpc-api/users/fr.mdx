Procédures du routeur `user`. Le compte lui-même (nom, langue, métadonnées) se lit et s’écrit en GraphQL ; ce routeur regroupe les vérifications qui demandent un accès au réseau côté serveur.

## Requête `user.checkEmailDomain`

Indique si un domaine peut recevoir des emails, en cherchant ses enregistrements MX. L’application l’appelle avant d’envoyer un code de connexion, pour signaler tout de suite une adresse dont le domaine n’existe pas ou n’a pas de serveur de messagerie. Cette procédure est publique, car elle sert avant toute connexion : elle reçoit donc le domaine seul, jamais l’adresse complète.

| Input | Type | Description |
| --- | --- | --- |
| `domain` | `String` | Domaine à vérifier, par exemple `example.com`. Requis. |

Elle renvoie `{ valid }`. `valid` vaut `false` quand le domaine est mal formé, inconnu, sans enregistrement MX, ou quand il déclare n’accepter aucun email. Une autre erreur DNS, comme une recherche qui dépasse deux secondes, ne met pas le domaine en cause : la réponse vaut alors `true`, pour que la connexion reste toujours possible. Le backend garde chaque réponse en mémoire pendant une heure.

```typescript
const { valid } = await trpc.user.checkEmailDomain.query({
  domain: 'example.com',
})
```

## Mutation `user.requestPasswordReset`

Envoie un email de réinitialisation de mot de passe. Cette procédure est publique, car elle est appelée depuis la page « mot de passe oublié », avant toute connexion.

| Input | Type | Description |
| --- | --- | --- |
| `email` | `String` | Email du compte. Requis. |
| `redirectTo` | `String` | URL vers laquelle le navigateur revient une fois le mot de passe réinitialisé. Requis. |

Elle génère le même type de ticket que Nhost Auth aurait lui-même émis, l'enregistre sur le compte, puis envoie par email un lien construit à partir de ce ticket. Ce lien passe toujours par le point de vérification d'Auth, donc la suite du parcours (vérification du ticket, reconnexion de l'utilisateur) reste inchangée. La réponse ne révèle jamais si le compte existe : un email inconnu, désactivé, ou pour lequel un ticket a déjà été émis il y a moins d'une minute, ne fait rien silencieusement.

```typescript
await trpc.user.requestPasswordReset.mutate({
  email: 'user@example.com',
  redirectTo: `${window.location.origin}/settings/credentials`,
})
```

## Mutation `user.requestEmailVerification`

Envoie un email de vérification d'adresse email, juste après l'inscription ou en renvoi. Publique, pour la même raison que `requestPasswordReset` : elle est appelée avec un email que l'appelant connaît déjà (celui qu'il vient d'utiliser pour s'inscrire, ou le sien), jamais celui de quelqu'un d'autre.

| Input | Type | Description |
| --- | --- | --- |
| `email` | `String` | Email du compte. Requis. |
| `redirectTo` | `String` | URL vers laquelle le navigateur revient une fois l'email vérifié. Optionnel. |

Même mécanisme que `requestPasswordReset` : elle génère le ticket que Nhost Auth aurait lui-même émis (valide 30 jours, comme le défaut d'Auth), l'enregistre sur le compte, puis envoie par email un lien construit à partir de ce ticket. Ne fait rien silencieusement si le compte n'existe pas, est déjà vérifié, ou a déjà reçu un ticket il y a moins d'une minute.

```typescript
await trpc.user.requestEmailVerification.mutate({
  email: 'user@example.com',
  redirectTo: window.location.href,
})
```
